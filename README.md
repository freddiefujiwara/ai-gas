# ai-gas

The owner's single AI gateway: one Apps Script Web App with two
windows, merged from the former muse-gas and groq-gas.

- **Muse window** — an HTTP bridge to Muse over email. Callers
  POST a request; this project sends it as an email from the owner's
  account to Muse's own mailbox (the address is managed in the
  `MUSE_EMAIL` script property, never in code), collects
  Muse's email reply, and serves it back over HTTP. Conversations
  can continue in the same mail thread.
- **Groq window** — a prompt proxy answering with the owner's Groq
  API key, keeping the exact interface the former groq-gas served to
  its callers (xuexi-gas, time-table-gas).

See `DESIGN.md` for the design and the decisions behind it.

## Muse window API

Every call needs the `API_TOKEN` script property, or a web session
token issued by `exchange_session` (see below). While the property is
unset, every call is refused.

| Call | Body / params | Returns |
| --- | --- | --- |
| POST | `{token, action:"ask", prompt}` | `{ok, id, status:"pending"}` |
| POST | `{token, action:"ask", prompt, engine:"groq"}` | `{ok, id, status:"replied", engine:"groq"}` — answered by Groq on the spot, no mail |
| POST | `{token, action:"answer", id, text}` | `{ok, id, status, round}` (Groq conversations resend their stored history) |
| POST | `{token, action:"rename", id, title}` | `{ok, id, title}` (max 100 chars; empty clears the name) |
| POST | `{token, action:"delete", id}` | `{ok, id}` (removes the sheet rows and trashes the conversation's attachment files; the mail thread itself is not deleted) |
| GET | `?token=...&action=result&id=...` | request status, `engine`, `title` + full message history; each message carries `attachments` (imported reply images as `{name, url, fileId}`, empty when none) |
| GET | `?token=...&action=list` | recent requests with `engine`, `title` and a `preview` (first outgoing line, max 50 chars; no full message bodies) |
| POST | `{action:"exchange_session", idToken}` | `{ok, sessionToken, expiresAt}` — Google ID token exchange for the web front end; only `ALLOWED_EMAIL` accounts pass |
| GET | `?action=rss&token=<RSS_TOKEN>` | RSS 2.0 feed of Muse's replies (newest first, max 20; Groq conversations excluded) |

The RSS feed uses its own `RSS_TOKEN` script property (generated by
`setup()`); the API token does not open it. Each item links to its
conversation's own thread URL (`https://freddiefujiwara.com/ai/<id>`)
and is titled with the conversation's display name.

Requests and messages are kept in this project's own spreadsheet
(sheets `requests` / `messages` / `sessions`) for 30 days. Reply
collection runs on a 1-minute time trigger that exists only while a
request is pending. Image attachments on Muse's replies are
imported into the Drive folder `API/ai` and served as lh3 URLs.

## Groq window API

Authenticates with the `GROQ_TOKEN` script property — a different
token from `API_TOKEN`, so neither window's callers gain the other.
Fails closed while unset. Answers are cached for 6 hours.

| Call | Body / params | Returns |
| --- | --- | --- |
| GET | `?p=<prompt>&token=<GROQ_TOKEN>` (`&cache=no` skips the cache) | `{prompt, answer, cached}` |
| POST | `{p \| prompt, token}` JSON body, token also accepted as a query parameter | `{prompt, answer, cached}` |
| POST | raw text body, `?token=<GROQ_TOKEN>` | `{prompt, answer, cached}` |

The model is the `GROQ_MODEL` script property (default
`openai/gpt-oss-120b`); the key is `GROQ_API_KEY`. Prompts are capped
at 20,000 characters.

## Setup

Run `setup()` once from the editor: it generates `API_TOKEN` and
`RSS_TOKEN` and creates the spreadsheet (unless `SPREADSHEET_ID` is
already set). Set the remaining properties by hand: `ALLOWED_EMAIL`,
`GOOGLE_CLIENT_ID`, `GROQ_TOKEN`, `GROQ_API_KEY`, and `MUSE_EMAIL`
(Muse's mailbox address, required), and optionally `GROQ_MODEL`.

## Development

- `npm test` — vitest with coverage
- `npm run build` — bundle `src/` into `dist/` for clasp
- CI deploys branch pushes to the staging project and `main` to
  production (secrets: `CLASPRC_JSON`, `DEPLOYMENT_ID`,
  `STAGING_SCRIPT_ID`, `STAGING_DEPLOYMENT_ID`).
